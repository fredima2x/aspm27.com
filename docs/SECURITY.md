# Security Policy

## Supported Versions

The following versions are currently receiving security updates:

| Version | Supported          |
| ------- | ------------------ |
| latest  | :white_check_mark: |
| < latest | :x:                |

## Reporting a Vulnerability

If you discover a security vulnerability, please **do not** open a public issue.

Instead, report it privately using one of the following methods:

- Use GitHub's [private vulnerability reporting](../../security/advisories/new) feature (available under the "Security" tab of this repository).

Please include as much of the following information as possible:

- A description of the vulnerability and its potential impact
- Steps to reproduce the issue (or a proof-of-concept, if available)
- The affected version(s) or commit hash
- Any relevant logs, screenshots, or configuration details

## Response Process

1. **Acknowledgment** — You will receive a response within **72 hours** confirming receipt of your report.
2. **Investigation** — The issue will be reviewed and its severity assessed.
3. **Fix & Release** — A fix will be developed and released as soon as reasonably possible, depending on severity.
4. **Disclosure** — Once a fix is available, the vulnerability will be disclosed publicly in a coordinated manner, crediting the reporter (unless anonymity is requested).

## Scope

This policy applies to the code contained in this repository. Vulnerabilities in third-party dependencies should be reported directly to the respective maintainers.

## Recognition

Reporters of valid, responsibly disclosed vulnerabilities will be credited in the release notes or a security advisory, unless they prefer to remain anonymous.
